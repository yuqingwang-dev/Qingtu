# 国内住宿起终点与真实交通规划

## 本轮范围

2026-09-17 已推广至北京、上海、杭州、成都单城市 1–3 天路线模式。每天最多 3 个主要地点，从所选住宿/地标出发，
可要求每天返回；按用户设置的出发与最晚结束时间排程。普通规划、其他城市、原有
国内外列表保持可用。更长行程可关闭真实路线模式继续使用原规划。

## 页面使用

1. 打开 http://localhost:3000/plan/single-city ，选择北京、上海、杭州或成都。
2. 选择三天日期、偏好与预算，出行方式选择公共交通（也支持步行、打车、自驾、混合）。
3. 勾选“按真实交通规划”。输入当前城市的酒店全名或附近地标，点击搜索，
   必须从结果中选择具体地点。此操作仅设置出发点，不预订酒店。
4. 设置 10:00 出发、20:00 最晚结束，勾选“每天返回住宿地点”。
5. 生成后查看酒店标记、各段道路、交通时长、预计返程时间、未安排地点与原因。
6. 首次构建矩阵可能需要 1–3 分钟；相同坐标/交通模式的查询可在缓存有效期内复用。

当前 DeepSeek 仍返回 401。普通规划无需模型成功即可生成真实路线；Agent 模式和
AI 解读需要用户更新根目录 .env 的 DEEPSEEK_API_KEY 后重启后端。高德 Key 已验证正常。

## 实现和边界

- TripPreferences 新增 use_real_routes、lodging、daily_start_time、daily_end_time、return_to_lodging。
  不支持的城市、缺少住宿、城市不一致、超过三天、结束早于出发等请求明确拒绝；不默默忽略。
- 先利用已有优化器选择/分配地点，真实路线模式优先选已核验 GCJ02 坐标的 POI，保留必去。
  泛称 seed 体验不当作已核验场所；需要时按中文名称和距离查询坐标，失败则标为估算。
- 一天至多 3 个主要地点，保证工具调用成本有界；超出部分记录在 unplanned，绝不无提示丢弃。
- AMapRouteProvider 使用 v3 walking / driving / transit/integrated；公交解析步行和公交/地铁
  分段。未实现火车/出租车组合公交的完整几何时，不伪装成完整公交线路。
- 起终点有方向，A→B 与 B→A 分开缓存；不假定对称。混合模式直线距离不超过 1km 时
  查询步行，否则查询公交。公共交通短途 <=1.5km 且无公交方案时另查真实步行并明确说明。
- 缓存优先 Redis，降级使用进程内限量缓存；默认 TTL 900 秒。默认最多 100 次路线请求、
  并发 3，单进程全局间隔约 0.55 秒；不是跨多 worker 的分布式限流。
- 矩阵使用当前查询快照，不传未来班次参数，不承诺未来堵车/停运/末班车可达。
  排程将该参考时长计入出发、等待、游玩和返程，预计结束时间满足用户时间窗。
- 每天进行全排列检查；跨天最多两轮地点交换，在必去优先、可安排数量优先的前提下，
  尝试减少总交通时间。同批地点/住宿/交通模式/矩阵快照才能比较 baseline 与 optimized。
  如丢弃地点导致集合变化，baseline/saved 返回 null；不利用删景点夸大“优化”。
- 真实时间窗仅来自已有数据，POI 未来开放时间未知时仍明确提示核实；未实现闭馆日、
  午休、多时间窗、真实预约或整日餐饮营养安排。交通费用不计入当前景点费用总计。
- 失败、限额、超时或未核验坐标产生 source=estimated，geometry 为空，界面显示估算。
  不拿直线连线冒充道路。地图实线为服务返回几何，虚线为缺失几何的示意。
- 地图加入“住”标记和实际线路，保存/分享 JSON 保留路线数据，相关页面也传入路线地图。
- 原有 AI 微调后会重新计算真实路线以避免展示过期路线；完整版本化重规划仍属后续步骤。
- 不保证全局最短路径。本轮已有优化器的 optimization_score 仍是原选择阶段评分，不是
  真实路线提升率；交通改善以 route_report 的同条件分钟对比为准。

## 配置

```env
ROUTE_MAX_REQUESTS=100
ROUTE_CACHE_TTL_SECONDS=900
ROUTE_TIMEOUT_SECONDS=90
```

修改后重启后端；Compose 已转发这些参数。RouteLeg 的 origin/destination/geometry
统一使用 GCJ02 并渲染在高德地图；未知坐标的估算区间不等于坐标已验证。

## 2026-09-17 城市推广验收

支持名单集中于 `backend/app/core/route_cities.py`。城市接口新增只读计算字段
`supports_real_routes`，前端按该字段展示入口。公交参数 city/cityd 和路线缓存键
均使用当前城市，不能把成都的公交上下文沿用到北京、上海或杭州。国外城市仍走原规划。

继续使用根目录 `D:\RouteMind\.env` 的 AMAP_WEB_SERVICE_KEY，不需要每城单独创建 Key。
本轮无数据库结构变更。冒烟脚本支持 `--city Beijing/Shanghai/Hangzhou/Chengdu`、
`--days 1/2/3`，例如：

```powershell
.\.venv\Scripts\python.exe scripts/smoke_routes.py --city Beijing --days 1
```

真实测试均为一日、三个地点、公共交通为主、10:00出发/20:00前返回；不是三城三天的完整视觉验收。
